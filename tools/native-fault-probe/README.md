# Synthetic native fault probe

This is a separate Android instrumentation APK for local emulator QA. It is not compiled into Show Control and has no production endpoint or network permission. Use only the repository's internal/test signing key and the isolated `ShowControl_QA_API35` emulator. Do not install it on a customer device or change the delivered app's debug flags.

`build.ps1` accepts explicit SDK, JDK, test keystore, original fixture, target APK and fresh output paths. It verifies the fixture and matching certificates, then packages with the existing SDK tools; no dependency download is needed. `FaultProbe` can locate/corrupt/restore only the SHA-256-named synthetic WAV embedded in the test APK. The target APK and its JavaScript/DEX/native bytes remain unchanged.

Start the instrument with a fresh UUID `token` against `app.showcontrol.nativefaultprobe/app.showcontrol.nativefaultprobe.FaultProbe`. It starts the app and publishes a Ready receipt in the target's external-files directory. `invoke.ps1` sends token/sequence-bound actions and saves immutable command/result receipts. Commands are `locate`, `corrupt`, `restore`, `finish`; sequence numbers begin at one. The app's normal UI and native media controls are exercised separately. Do not call Start Instrumentation during a prepared show: Android starts a fresh process.

The scan is confined to canonical app-owned files, bounded by depth/count/size, and requires exactly one fixture match. Corruption requires the known original bytes. Replacement is atomic. Restoration validates both the embedded original and the current known damaged bytes. Unknown contents are preserved and reported rather than overwritten. Normal finish, idle/overall timeout and caught helper failures attempt restoration. A killed process cannot run cleanup; re-start the same helper and `locate` to repair only the exact known damaged payload, then verify `restore` before continuing. Never delete app data as recovery.

After testing, require a receipt with the original checksum and `corruptActive:false`; finish, uninstall the probe package, remove only this session's control files, restore synthetic fixtures/settings and verify the app is idle. Record installed identity, instrumented status, observed behavior, failures and limitations. Instrumentation is not physical/audible/two-hour evidence and does not prove the historical renderer ANR fixed.

## Incoming-readiness instrument

`ReadinessProbe` is a separate instrumentation entry point in the same test APK. It never writes media or dispatches transport. Start it before preparing a show with a fresh token, then use normal UI to prepare/start the tagged QA outgoing loop. Invoke `arm` with `invoke.ps1 -Probe readiness`; the next incoming admission must contain exactly one checksum-verified synthetic WAV. Existing fault actions remain unchanged with the default `-Probe fault`.

The instrument replaces only that prepared incoming player's service listener, on its native owner looper after the admission message finishes. All events are forwarded except READY. The production five-second timer and resource cleanup remain untouched. `status` reports actual native state, staged/active resources, the held gate and real READY suppression count. `lateReady` deliberately calls the original listener only after refusal/cancellation and staging release, testing stale callbacks. It is synthetic callback injection, not a real decoder hang. The tool refuses active outgoing cues without the QA tag and never changes their listeners.

`disarm` removes the one-shot looper observation; `finish` requires no active/pending voices or an already-destroyed owner. Normal Stop/exit occurs through the app. Neither action delivers READY to a still-pending incoming voice. The bounded instrument ends without restoring a withheld callback to a live voice; the production timeout remains responsible for refusing it. See [the installed timeout plan and evidence](../../docs/native-readiness-timeout-2026-10-24.md). The helper is tied to the pinned Media3 internals and must be rebuilt/re-audited after a library upgrade. It is never part of a delivered APK.
