# Native rehearsal seek isolation instrument

Separate same-public-test-signer Android instrumentation for the parent-owned `ShowControl_SingleButton_QA` at `emulator-5564`. It is never bundled or registered in Show Control. It uses the installed release APK's real runtime and command queue; no Metro/debug client, product endpoint, provider call or library write is involved. Keep host audio disabled. Its UUID-owned original WAV contains zero PCM and every cue uses −96 dB.

The 11 cases verify main/Hit same-cue isolation at 0.7× and 2×, native paused silence, saved and actual rates, precise absolute-source seeks, trim clamps, deliberate source-clock resume, different-cue refusal, and Hit-only refusal without ACK. A legacy group leaves a carried main-sequence voice sharing the primary's cue ID; seeking must preserve that voice too. Positions, pause and rates are read synchronously on the real owner looper. After decoder readiness and initial movement, source clocks are measured for at least 800 ms with a 15% plus 20 ms tolerance that distinguishes an incorrect 1× clock. Native broadcasts supply exported command ACK timestamps/generations, avoiding JavaScript delivery assumptions. Every preparation gets its own UUID-derived show identity; ACK admission filters that identity and its native generation. This is native-state emulator evidence; it does not prove acoustic output, pitch preservation, physical hardware, iOS or customer readiness. Audition compatibility remains covered separately by the existing preview lifecycle instrument.

Snapshots include the complete canonical media array and show/set names so normal late app-session attachment can validate them. Failure output retains a bounded cause chain/stack, observation stage and last safe owner sample. Shutdown waits for its accepted owner to detach; a different owner is preserved. The first instrumented attempt recorded only two passing 0.7× cases before an owner-observation failure; its discarded inner cause prevents assigning that failure to a specific trigger.

Build into a fresh output directory with `build.ps1 -Sdk <sdk> -Jdk <jdk> -DebugKeystore <public-repository-test-key> -TargetApk <exact-release-apk> -Output <fresh-path>`. The helper and target certificates must match. Install only the helper after verifying the target, then invoke `invoke.ps1 -RunId <fresh-lowercase-uuid> -ExpectedApk <exact-release-apk> -ProbeMetadata <output/metadata.json>`. Package, target/helper installed hashes, source hashes and the exact AVD/serial are checked. Existing probe guards remain unchanged.

Begin with an initialized synthetic library, no prepared audio/voice/download service and no other instrumentation. Android can stop the target process when instrumentation starts. The instrument independently requires no native owner, pending preparation or critical admission before it begins. It launches the ordinary app, creates one uniquely named WAV directly under app files outside the library, and runs ephemeral snapshots. Ownership is acquired only after accepted preparation and UUID identity validation. Within one native owner-queue turn, it validates that exact service, immutable prepared object and generation, then invokes production `executeCommand` or `shutdownOnCommands`; changed/refused ownership preserves the new owner. This is a focused native command-body proof, not a test of JavaScript dispatch or safety-priority queue admission. Parent operators must not interact with or prepare another session during this isolated test.

After shutdown it compares the logical digest of eight canonical SQLite tables (including `library_settings`) and checksum-guards deletion of only its own WAV. Each digest uses API 35's read-only transaction so all tables include the same committed WAL snapshot; journal bytes and checkpoint timing are not mistaken for data changes. This digest does not cover original media bytes, secure storage or shared-preference files. The helper changes no sound, notification, focus-policy or battery setting; normal native preparation/resume requests audio focus and shutdown releases it. It never reads original media, API keys or controller credentials.

Retain `handle.json`, command observations, complete instrumentation output and `terminal.json` under `.native-check/rehearsal-seek-run-<uuid>/`. Output includes source/rate/pause observations, ACK/fault events with session/generation/timestamps, and before/after canonical-table digests. Passing requires all 11 cases, `passed=true`, `nativeOwnerReleased=true`, `ownedFilesRemoved=true`, `libraryTablesUnchanged=true`, `INSTRUMENTATION_CODE: -1` and a recognized successful service dump with no remaining service. Missing/pending evidence is not a pass. A deadline preserves a live handle; reconcile that exact process instead of restarting or stopping a live owner. After inspecting the receipt, uninstall only `app.showcontrol.rehearsalseekprobe`, verify a silent relaunch and preserve the original library/preferences.
