# Audition lifecycle instrument

Separate same-test-signer instrumentation for the isolated `ShowControl_QA_API35` only. No production endpoint, manifest registration in the product, permission, network, provider request or library write. It verifies the exact installed APK, creates one uniquely named original synthetic WAV outside the library, and exercises native runtime calls with ephemeral QA snapshots at −96 dB. Host audio must be disabled. This is emulator/native-state evidence, not acoustic or physical-device proof.

The instrument checks idle, active, paused and natural-end Stop, duplicate Stop, both stop/prepare queue orderings, protected playing main audio, rejected stale work, failure cleanup and fresh Retry. Its short command-queue hold only establishes deterministic ordering and is always released; it does not change the production queue or audio behavior. Seventeen separate JVM regressions run the actual runtime/teardown source with controlled platform dependencies, including startup cancellation and shutdown failure cases unavailable through ordinary UI.

Use fresh build/output/run IDs and the exact target checksum. Start only with no prepared service or active instrumentation. Preserve any live operation handle after observer timeout; do not restart the instrument or target. Finish requires native shutdown and checksum-guarded deletion of only its own WAV. Unexpected files are preserved. Uninstall only the helper after inspecting terminal receipts, verify original library/preferences and no service/media owner, then close the owned idle emulator. No original media or provider keys are read.
