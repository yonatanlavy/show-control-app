# Native endurance fixture

`node tools/android-endurance/New-EnduranceFixture.mjs` creates a fresh, explicitly synthetic backup under `.native-check/native-endurance-<uuid>/`. It reads the actual pure canonical constructors/compiler/manifest/ZIP writer through a restricted fixture-only TypeScript loader. It generates an original quiet PCM tone, checks both transport modes with the compiler, then validates the stored archive and every extracted CRC/content. It contacts no app, credentials, provider or network and never overwrites an existing fixture.

Import `endurance.zip` through the app's normal **Import library backup** on an owned test device only. This adds a new independent QA show and selects it; restore applies its documented preference/rebinding/calibration behavior. It is not a production library or performance soundtrack. Keep the original library/selection/preferences baseline, retain the synthetic show deliberately, and restore the original selection/preferences after testing. Never inject it into a performer's library or use import to replace existing work.

The primary OMS set has one trimmed 1.25x main loop and an independent **Seven looping Hits** group. Its seven children use 0.7x–2x rates and 500–7,000-ms source trims; ordinary fade tuning is intentionally longer than the shortest loops. Starting the main, then that Hit group, exercises eight native voices. An additional single Hit and a manual advance expose deliberate capacity-refusal cases. The second set offers an eight-child legacy group for a separately recorded compatibility run. Every start is explicit; importing/preparing must stay silent.

A two-hour observation must name the exact APK, device/OS, session purpose, native owner/PID, start/end times, actual periodic states, errors and stop/exit/relaunch results. Keep observers' live handles; a timeout is not permission to restart a show or an observer. No host audio, silent PCM, an emulator or a reported voice count proves acoustic gain, seamless loops, pitch, physical routing, remote delivery or two-platform reliability. Physical acceptance remains required.

`Test-Observation.ps1` runs offline rejection cases against the actual observation functions. `Watch-Endurance.ps1 -RunId <fresh-uuid> -ExpectedApk <absolute-apk> -DurationSeconds 7200` observes an already deliberately started run on the exact owned API-35 emulator. It verifies the installed hash, native foreground/media owner and PID, source clock/rate, no battery exemption and Android ANR state. It dispatches no playback commands. `-ValidateOnly` prints the bounded observation schedule without contacting the device.

The default `NativeHierarchy` mode requires eight voices and the expected main title in each hierarchy observation. If the continually updating live clock prevents Android's test dumper from becoming idle, choose `-UiMode Screenshot` **before starting a fresh run**. That mode waits one bounded second after wake for composition, retains screenshots for explicit image review and reports automated voice-count evidence as false. Main MediaSession playback alone cannot certify that all eight voices persist. Never convert a failed live run into a pass by silently switching observation modes. A blank screenshot stays unavailable evidence; inspect it and investigate a fresh controlled observation rather than calling it a visual pass.

Keep the returned process handle until `terminal.json` confirms completion, inspect every screenshot and preserve failures. The watcher leaves audio playing and can leave simulated discharging/Doze overrides. Deliberately stop/panic through the app, verify all native voices stop, exit the session and check a silent relaunch. Restore the original selection/preferences, `cmd deviceidle unforce` and `dumpsys battery reset` on the owned device. Shut down only that owned emulator after all app owners are idle. A shorter run must be labelled with its actual duration; it does not satisfy the two-hour gate.
