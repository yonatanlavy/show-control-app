# Installed keyboard focus/admission probe

Separate same-public-test-signer instrumentation for the owned synthetic QA AVD and exact provisional app APK. Never ship it or attach it to a real/prepared show. Verify no audio service, armed/pending preparation, diagnostics or user interaction first. Instrumentation can end the target process.

The probe explicitly configures an ephemeral native controller context without starting Flic/service capture, temporarily owns a synthetic native profile in memory, adds its own empty native EditText, and uses production HardwareKeyCapture's synchronous bridge route with a fake native armed flag and an isolated command receiver. Idle Library does not configure capture automatically. It prepares **no audio** and edits no persisted profile/library/media. It verifies actual native focus observation, no raw controller events or semantic broadcast for typing/held keys, fresh released GO admission, and assigned panic/stop while editing. This is synthetic input/admission evidence, not real external-HID, hardware delivery or acoustic playback proof.

The original in-memory profile and native idle state are restored in `finally`; its temporary field, capture, observer and receiver are removed. No key/receipt/media/library data is exported. Result counts and status are written to one UUID-owned `keyboard-text-<token>.json`. Inspect `INSTRUMENTATION_CODE: 0` and absence of error/cleanupError; shell exit alone is insufficient. On failure, reconcile the existing process and receipt instead of restarting a live owner. Remove only the helper and exact token-owned remote file after preserving local evidence.
