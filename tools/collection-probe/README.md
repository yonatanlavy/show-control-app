# Isolated collection fixture

Separate same-test-signer instrumentation for the isolated fixtures described below. Nothing in this folder is shipped or registered in the product. The legacy seed operation on ShowControl_QA_API35 appends 601 uniquely owned shows: one has 1,200 ordered songs and 200 Hits, sharing one original synthesized PCM file. The fixture generator uses the canonical constructors and validator. It reads no user media or API keys and sends no network requests. Original document rows are hashed locally; existing selection/preferences are captured opaquely in a private marker solely to guard cleanup and restore the fixture-owned selection.

Build with a fresh UUID/fixture output and the exact target APK. Invoke seed only on the isolated idle emulator, with no active service or instrumentation. Opening the library does not select or play the fixture; select QA Collection Large deliberately through the app. Do not run an assistant. Restore locale/theme preferences before clean.

Measure is read-only: it opens the ordinary English Library, waits for its search field, then counts actual Android views and collection-row descriptions on the UI queue. UIAutomator prunes offscreen entries, so its XML count must not be represented as the number of mounted native rows. The bounded view count is architectural evidence on this emulator, not a device-performance benchmark. Original rows are hash-checked before/after measurement, and the owned activity closes afterward.

`measure-rehearsal` is a separate read-only path restricted by the wrapper to the owned `ShowControl_LibraryLoad_QA` device at `emulator-5564`. It never seeds or cleans there. It requires only UUID-labelled synthetic Recovery/Rehearsal shows and a selected rehearsal fixture, opens SQLite read-only, follows the ordinary `showcontrol://rehearsal` route and waits for silent Prepare. It counts real mounted Android views and synthetic song/Hit title TextViews, not UIAutomator's pruned XML. It compares all original show/trash/revision rows before/after, leaves the selection unchanged and closes its activity. The legacy Library measurement retains its original seeded-marker requirement.

`inspect-import` is a separate read-only check after importing the exact fixture WAV through the app, attempting invalid audio/artwork and cancelling pickers. It requires exactly one added song with unchanged new-song tuning, one shared canonical media asset, no saved visual and no remaining staging files. It checks original rows/preferences and rejects assistant work. It cannot reproduce a delayed native reader or prove physical storage behavior.

The tool creates a durable ownership marker before file/SQL writes, rejects identity/checksum collisions, appends metadata transactionally, and checks hashes of original show/trash/revision rows. Cleanup is explicit and checksum/marker guarded. It removes only recorded show IDs, their revisions/trash and the exact synthesized asset, refuses media references outside the fixture, preserves settings, and restores the captured selection only if the fixture owns it. Original changes, changed preferences, unexpected assistant work or changed media stop cleanup for inspection. No recursive removal is used.

An observer timeout is not permission to restart, seed again or remove the marker. Reconcile the same process/instrumentation handle. A failed seed retains its intent marker for deliberate clean. Preserve evidence and original data when a guard fails. Terminal reporting still runs if database/activity cleanup throws, and such cleanup failure cannot be reported as a pass. Stored media URIs use the same logical files-directory path as Expo; canonical file identity is checked separately so Android's `/data/user/0` alias is not rewritten to `/data/data`. Cleanup records that URI and remains compatible with older markers. This fixture bypasses ingestion to isolate list UI; seeding alone does not prove picker/import, cross-platform restore, physical performance or long-run reliability.
