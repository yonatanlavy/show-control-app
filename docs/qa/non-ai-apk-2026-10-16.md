## Fixes and acceptance evidence

- Playback commands queued behind an old bridge dispatch are invalidated when preparing, exiting or shutting down a session. Commands are rejected while an exit is pending; stale preparation, reconciliation and exit completions cannot overwrite a newer session. Five new deterministic regressions cover these boundaries.
- Remote learning/testing uses the Activity window instead of a native Modal, whose Android key-down path bypassed the HID adapter. Hardware Back and Close end diagnostics. Repeated setup taps cannot start overlapping sessions. Pairing exceptions, cancellation and timeout publish terminal states, and obsolete SDK callbacks cannot settle a newer scan. Focused controller tests and a pure Kotlin pairing-lifecycle regression cover these changes.
- Managed media promotion copies to a tracked staging file, verifies bytes/hash, and then renames on the same volume. Failed copies can be retried; damaged canonical files are retained in recovery and can be repaired during ordinary import or backup restore. Separate adapters serialize promotion of the same canonical path and report creation ownership truthfully. Cancellation/idle guards run before mutation. Regression fixtures cover partial copy, rollback, concurrent promotion and cancelled commits.
- A finished download whose target disappeared remains available to attach/share. The interface reports the missing target and does not announce success or hide the retained download. No download/provider network request was needed to test this path.
- Changing language/system text size exposed a transient SQLite lock during Activity/bridge recreation. A current library was unnecessarily re-migrating and rewriting all show documents on every reopen. Startup now validates the known completed migration ledger and reopens current libraries without that write; preserves foreign keys/WAL; uses a one-second connection busy timeout; and retries only transient startup reads, twice. Mutations and migration bodies are never replayed. A real two-connection regression holds an uncommitted settings save while reopening the library. Corruption, future history and persistent locks still fail closed with deliberate Retry, now with specific busy guidance in all ten languages.
- Run elapsed/remaining clocks now convert source-relative progress using the active song's playback speed, matching Rehearsal. The progress ratio and native source-time seeking remain unchanged. Four regressions cover 0.7×, 1.5×, 2× and the legacy 1× default without layout changes.
- The final Run arming pass exposed an Android service-startup crash: transport creation blocked the main thread, then threw after a two-second deadline. Startup now runs on its owning command thread, including looper initialization, with the same bounded deadline. Timeout/cancellation prevents late publication and releases an unpublished player on its owning thread. Partial teardown checks initialized resources and registered receivers. Failed pending prepare/preview promises settle after destruction so Retry creates a fresh owner, without a stale playback fault event. Startup attachment, pending work, Stop Preview and shutdown coordinate under one ownership lock. The pure Kotlin regression covers successful transfer, timeout, cancellation, late completion, fresh retry, single disposal and 100 concurrent complete/cancel races. This is separate from the pressure-related first-launch ANR described below.
