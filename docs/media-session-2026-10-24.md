# Background protection and native system controls · 24 October 2026

## Outcome and scope

Strengthen the deliberately prepared show's foreground ownership and keep its visible return shortcut available while Ready, paused, waiting or recovering. Playing shows retain native system media controls. The existing background readiness panel reports battery exclusion, background restriction, Power Saver, permission, channel and service readings; unknown readings stay unknown. It offers deliberate Settings repair while idle, refreshes on return, and prevents preparation during pending Settings/permission interactions.

This is progress toward the continuing customer-readiness goal, not a complete release certification. Source promotion is limited to 21 explicitly listed files. User media, show revisions, provider keys, dependencies, persisted schema, GO/panic geometry and unrelated working changes are preserved. No AI/provider requests were made. This pass changes Android native behavior and shared translated guidance, without claiming new iOS device evidence.

## Plan and implementation

1. Replace the private silent renderer's public MediaSession with a semantic player that projects native prepared, waiting, audible, paused, recovery and closed state. The private renderer retains its existing wake/failure policy. The public adapter renders no audio, schedules no playback and exposes no imported source URI, arbitrary seek, speed mutation or media editing.
2. Own notification updates and foreground retention through MediaSessionService's supported override. Do not invoke the default provider's delayed/asynchronous update path. A deliberately prepared show stays protected independently from public playWhenReady. Preview/setup do not acquire a prepared-show notification; exit releases it.
3. Fence notification actions by immutable owner identity and captured native command epoch. Carry that epoch through queue admission; Stop advances the epoch atomically and preempts stale work. Untrusted new controllers are rejected. Exported service Intents are not a command channel; authenticated framework media controls remain supported.
4. Verify actual notification buttons, OS media controls, locked idle retention, notification return, task removal and silent relaunch on an isolated API 35 emulator. Bind the installed bytes, source map and retained native safety fixes to the delivered APK.

Main progress belongs to the actual main voice, with source-time bounds and saved rate. Independent Hits never supply its progress. Ready is PAUSED at zero; countdown is waiting; audible voices play; native pause freezes progress; recovery exposes safety without start/navigation. Native GO eligibility suppresses Next during transitions. Standard status buttons use localized GO, Resume and Stop labels. The existing fixed in-app transport is unchanged.

Ready, pause, waiting and recovery use an ongoing BigText status notification. Playing uses MediaStyle. The low-importance channel is silent and non-vibrating. Battery/background restrictions and Power Saver produce an advisory; recovery instructions take precedence. General notification permission is required for the idle status to be visible, while live media controls retain the platform exemption. All ten languages explain this distinction. Denial does not block local playback. A failure to establish foreground protection latches mute, invalidates commands and stops for deliberate recovery. Explicit system stop/force-close remains authoritative; START_NOT_STICKY prevents automatic playback recreation.

## Findings corrected during acceptance

The first exploratory candidate rejected genuine legacy framework Pause callbacks with unknown identities. Controller admission remains checked, but that overstrict framework callback check was removed. A second candidate retained its native process and foreground service for 665.137 seconds, yet Android hid the paused media card. This failed visible-return acceptance and led to the standard ongoing idle status. Later candidates refined localized action labels and native GO eligibility. Testing the actual generic GO button then exposed a URI/filter mismatch: the private broadcast carried a URI, but its receiver filter accepted no scheme. The final filter explicitly accepts the notification scheme. These candidates are superseded; their exact bytes and raw failed observations are retained under `.native-check/rejected-*`.

Media3 1.10.1 always publishes a legacy ACTION_SET_RATING flag regardless of the empty granted SessionCommands. Rating/custom requests remain ungranted; the raw compatibility bit is not claimed removed. No dependency patch or reflection hides it. A changing live media card also prevented one UIAutomator idle dump; an actual screenshot and successful card Pause test provide the relevant evidence instead.

## Limits and remaining release gates

Android can terminate or let users dismiss foreground services/notifications. Battery exclusion reduces restrictions and cannot guarantee survival. OEM policies, actual audio, calls/alarms/DND, exact remotes/Flic, microphones, HDMI, cross-platform transfer and two-hour runs still require physical evidence. iOS needs macOS/Xcode or a build service and physical validation. The historical focus/rendering ANR from 23 October remains unresolved; a successful current return/relaunch does not establish its cause or close it. Complete parity and readiness for customer distribution remain open.
