# Audience display refinement · 14 October 2026

The reference calls for a dedicated audience screen while the operator keeps private controls. The setup now distinguishes physical display detection from an enabled, connected renderer. It includes a static original diagram, HDMI/privacy guidance, three setup steps, a silent border/centre test, an image-only default picker with replacement and confirmed detachment, visual precedence, native diagnostics, retry and immediate display blackout. It adds no animations, account, AI provider calls or schema migration.

`VisualStatus` adds `displayDetected`, `testing` and an optional visual-only error code. The native `testPattern` method requires idle audio through the existing shared coordinator, accepts bounded translated labels, and draws without starting audio. `endTestPattern` clears only an active test; navigation/background cleanup cannot blackout an already prepared show after the test was cleared. Native visual setup depends on ShowAudio for this guard, without dispatching any audio command.

Both renderers retain a generation floor and monotonic blackout barrier after clearing the visible latch. Events produced before prepare, disable, blackout, failure or safety stop cannot resurrect an old visual. A deliberate new start can keep the same generation if its native timestamp is newer. Decoder/seek callbacks also carry a renderer revision so an old video cannot alter a replacement. Native audio PROGRESS is already relative to the song's trimmed start, so the audience renderer uses it directly; it starts at zero and follows trim-relative seeks/loops without subtracting trim a second time. Disable also clears the iOS latched state.
